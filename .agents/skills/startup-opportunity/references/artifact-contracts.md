# Artifact Contracts

本仓库只支持 `harness/schemas/current.json` 指定的 current contract。代码、schema、policy、template 或 fixture 更新后必须使用新的 `run_id`；旧 Run 可以在普通 current Manifest/schema 校验中失败，不得检测、迁移、适配、降级读取或选择历史 bundle。

同一个 current Run 内仍保持强恢复保证：`manifest.json` 是原子替换的 current index；正式 envelope、checkpoint、Plan revision、Gap Snapshot 和 Adaptation Decision 都按不可变路径发布；Event、Decision 与 Evidence substrate JSONL append-only；receipt replay、checkpoint/reopen 和 crash recovery 只消费已验证的 on-disk bytes。

Scope 是 Run Store 领域不变量。`create-run` 只能把 main agent 提出的 Scope proposal 作为 revision 1 原子追加到 `decisions.jsonl`，Manifest 绑定 proposal 的 exact ref/hash 并进入 `awaiting_scope_confirmation`。调用方把该精确 proposal 展示给用户后，必须以独立 `confirm-scope` 操作绑定 revision/ref/hash；确认记录明确标为 caller-attested，Harness 不具备聊天身份认证能力。用户修正使用 `propose-scope` 追加新 proposal，再独立确认，绝不覆盖旧记录。确认前所有执行入口拒绝计划、搜索、Evidence 写入与普通下游发布；修正确认后继续拒绝执行，直到 Plan 对账完成。`status-run` 和 reopen 都从持久化记录证明当前绑定，调用方布尔值不能代替确认。

正式研究状态位于 `runs/<run_id>/`。chat、任务摘要、subagent 完成消息以及 `dist/research-working/<run_id>/` 的临时 JSON 都不是正式 Artifact。安全工作目录用于 caller staging；`materialize-lane-result` 消费 caller-supplied staging document、exact Evidence receipts 和 current Manifest，并通过与 `compile-artifacts` 相同的 ref resolver、closure、publication plan 和 Store 路径生成正式 envelope。

跨 Run 语义只有一个显式准入和读取入口：当前 opportunity-discovery Run 的 Scope 必须已经确认且 current Plan 已经发布；在读取旧 Map、Candidate 或结论内容之前，main agent 必须调用 `admit-prior-input`，同时指定当前 `run_id`、source `run_id`、单个 exact Run-relative source path、唯一且尚未发布的当前 Map/Candidate target artifact path、prior input id、`discovery_maps | discovery_candidates` consumer 和使用理由。Store 直接 hash 指定文件的原始 bytes，向当前 `decisions.jsonl` 追加唯一 `prior_input_admitted`，并只返回 receipt/ref/hash。语义 bytes 只能通过 `read-prior-input` 消费 exact admission ref；Store 重新 hash bytes，并先追加 `prior_input_consumed` 再返回内容。已有 consumption 的 exact replay 复用首次消费时记录的 immutable taint exemption boundary，不根据后来扩大的 Manifest 重算。hook 对能解析到或可能位于受控 `runs/` 根的 direct、dynamic、glob、variable 和 `find` 读取 fail closed；普通 repo、staging 和 tmp 读取不受影响。由于同一 Agent 不具备可靠的 target 上下文隔离，消费后的 admission 保守 taint 所有尚未发布的 Map/Candidate：它们必须标为 `prior_informed_synthesis`、传播 exact admission ref，并保持 `hypothesis_input_only`。该 taint 只证明 provenance，不影响 Gate、淘汰、排序、Claim confidence、recommendation ceiling、Lane success 或其他决策资格。Store 不扫描旧 Run、不选择旧 schema、不恢复旧 Run。通用 Decision append 不能创建 admission/consumption；仅替换旧文件的 run_id、时间或 lineage 永远不能把它变成本次 discovery。

正式 ref 分类只有以下权威语义：Run Artifact、Run Artifact fragment、JSON Pointer、exact Evidence/Event/Decision record、repo policy JSON ref 和外部 HTTP(S) URL。Evidence raw bytes 由 exact Evidence substrate record 的 hash/ref 绑定，不伪装成 JSON Artifact。编译 validate-only 输出不可变 publication plan；publish 必须消费同一 plan，并在 current Manifest 或 closure 漂移时失败。

Evidence、Claim、Finding、Insight 和 Judgment Assessment 是不同层。决定性事实、引文、反对材料和建议必须追溯到真实 Evidence。来源需显式记录 provenance、independence、bias、retrieved_at、published_at、observed_at、data_period_end、evidence character 和 limitations；valid_as_of 由 current 规则推导。Harness 不从 URL、内容或聊天推断这些判断。

`startup_opportunity.commercial_research_delivery.current` 是 Lane 提交的宽松研究语义输入；`startup_opportunity.commercial_research_audit.current` 是 Harness compiler 生成的 discovery/assessment 正式 Artifact，不是 Lane 直接编写或 API 专用旁路。Delivery 只需关闭 Dispatch 分配的 metric families、competitor types 和 incumbent response subjects；Harness 补齐 assigned coverage closure、unavailable/partial/unknown 行、ID/hash/ref、freshness、来源分布、ranking、ceiling 和报告投影。八个量化 family 与七类 broad substitute 的整体计划覆盖在 candidate/Wave/report 聚合显示，不转嫁为每 Lane authoring 格式成本。

Incumbent Response assignment 的 depth 只有 `not_assigned | lightweight_scan | targeted_deep_dive`，role 只有 `none | owner | independent_review`。Execution Plan 是唯一权威；每个响应研究 stage 恰有一个 owner，独立复核必须显式角色化，其余 Lane 为 `not_assigned/none`。所有状态（包括 `not_assigned`）都必须按 Plan -> Dispatch -> Task -> Audit exact 投影，缺失或漂移是 integrity error，不允许回退由 Task 决定 assignment。候选形成前必须 `not_assigned`；形成后的候选可做 lightweight scan，shortlist/retained opportunity 或 formed concept 的 commercial stage 可做 targeted deep dive。`assessed` Delivery 只记录完整的结构化 responder 研究维度，不允许 Agent 编写 `strategic_implication`、pass/fail、淘汰或 ceiling 指令；Compiler 为所有正式状态注入同一个 reference-only strategic context，Schema、商业 validator 和报告 projection 都验证或强制该边界。`unknown` 输入含 uncertainty/unknowns/data gaps，并可选保留 supporting/opposing/background refs；`not_applicable` 只含理由与可选 background refs，由 Harness 扩展成统一正式行。`unknown` 的统一 rationale 只表示提交材料与语义不足以形成完整 responder-specific conclusion，不推断没有研究或没有 Evidence；强风险维度仍安全展开为 unknown/空，可选 refs 继续按 same-Audit Evidence Register、exact ref/hash、Run 和安全边界校验并投影到三种正式报告。`unknown` 进入 Search Closure 和报告 gap，`not_applicable` 不形成 gap。该 Artifact 只作 judgment context，不进入 Gate、ranking eligibility、Claim confidence 或 recommendation ceiling 派生，也不阻塞发布。

Acquisition provider 为开放字符串，但 raw response ref/hash、exact Evidence substrate、脱敏和 access-control const 必须闭合。新闻、评论、论坛、厂商、监管、API/数据集、proxy、estimate、支持、反对和背景 Evidence 都保留；rejected Evidence 可用于反证、来源排除和局限。rejected 或未纳入 Audit Register 的 Evidence 不能算作直接正向支持，Harness 降低相关 Claim confidence 或 recommendation ceiling并输出诊断，而不是因来源偏弱删除材料或使 Lane 整体失败。不存在、跨 Run、类型/hash 错误的 ref 仍是 error。

producer role 使用 `main_agent`、`lane_researcher`、`evidence_auditor`、`adversarial_reviewer` 或 `harness`；agent 配置名仍使用仓库文件名 `lane-researcher` 等。正式 Evidence JSON 位于 `evidence/records/`，raw bytes 位于 `evidence/raw/`，exact substrate ref 使用 `evidence/manifest.jsonl#<evidence_id>`。每个 lane 只拥有 task 指定的唯一 output path。

每次候选、fan-in、conversion、下游综合和终态报告发布前，Run transition guard 必须拒绝未完成 operation、未处置 blocking Gap、pending Adaptation Decision 或仍有 active unit 的 fan-in。Plan 变更只能按 Gap Snapshot -> Adaptation Decision -> policy validation -> immutable Plan Revision -> checkpoint 顺序执行。

终态报告必须在原研究 Run 上生成。`insufficient_evidence`、部分执行、runtime degraded/blocked/failed 都可以如实报告，但不能创建 reporting continuation Run 绕过原 Run 状态。Manifest 的 current decision subject snapshot 是唯一主体 authority；每个 current/final subject 需要一个 immutable `decision_subject_synthesis`，绑定 exact subject ref/hash 和 same-Run synthesis basis，并承载完整自然语言 Direction 与该主体的验证步骤。terminal source 通过 exact synthesis ref/hash 绑定，Harness 从 synthesis 投影全部可见字段；历史、中间、dropped 或 superseded 主体只能留在审计范围，不能补主报告正文。

dropped/superseded 主体不得靠同一 ref、仅改 revision/path 或任意 Artifact hash 列表恢复。确需重新形成时，Candidate 使用 direct `parent_candidate_ref/hash` revision，Opportunity Thesis 使用 direct `parent_opportunity_ref/hash` revision，Concept 从无 revision 字段的初始 r1 进入显式 `parent_concept_ref/hash` r2+；新主体业务语义必须实际变化。至少一个 causal input 必须由 Store 在 terminal snapshot 之后、新 subject 之前正式发布，并实际进入该 subject kind 的 formation/synthesis closure。`created_at` 只作逻辑时间和展示，不能证明因果顺序；Artifact receipt 中 Harness-owned `publication_ordinal` 是唯一顺序证明。随后只通过 `reform-decision-subject` 生成 `subject_reformed` Decision，exact 绑定 subject kind、terminal snapshot/subject、新 subject、inputs 及其 Store ordinals；新 snapshot 仅引用该 Decision。普通 subject 不携带空 reformation 字段。checkpoint/reopen 会按同一 receipts 重放因果约束。

所有 validated Evidence 必须在 source 中采用或明确排除；用户 Markdown view 与结构化工程审计数据分离。

`report.json`/terminal source 的 `commercial_research_audit_refs` 由 Harness 从 Manifest 自动闭合所有 current formal Audit；`quantitative_signal_rows`、`competitive_substitute_rows`、`incumbent_response_risk_rows` 和 `research_coverage_gaps` 是这些 Audit 的 exact complete projection。caller 漏 ref 或重复表格由 compiler 覆盖；计划 task 确实缺少 Audit 时必须作为 warning、数据缺口和 decision impact 明确展示，不得静默生成空表。编译后正式 projection/hash 漂移在 publication、replay 和 recovery 中仍 fail closed。

Artifact、Store、schema、report 或 recovery 成功都只证明机械 contract，不证明来源真实、Evidence 充分、市场已验证、产品可行或建议正确。
