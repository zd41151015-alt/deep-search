# Reporting Ownership

G1.4 owns concept-assessment `report.json`, decision brief, full report, traceability, and consistency evaluation. G2.4 extends the same structured-source rule to discovery comparison and portfolio outputs.

`audit-traceability` consumes one explicit closed assessment or discovery bundle and returns a structured, non-zero-on-failure audit. `build-report` consumes one explicit current non-terminal assessment or discovery report envelope, then publishes `report.json`, `decision-brief.md`, core `report.md`, complete `audit-appendix.md`, and consistency sidecars in fixed order from one final report model. A `terminal_report_source.v1` is accepted only through `apply-plan-revision`, whose terminal closeout dry-runs and durably commits the status transition, Plan receipt, formal report sidecars, and materialized outputs with Manifest last. The public `build-report` API rejects terminal sources so it cannot recreate a terminal-without-report window. Terminal reporting handles complete or early-exit delivery without inventing unexecuted comparison/portfolio Artifacts. It localizes fixed text and enums from `research_language`, keeps readable sources in the primary brief, moves internal refs to the audit appendix, and renders ordered, testable product hypotheses from caller-supplied judgment. Exact replay is byte-stable; same-path, receipt, source/hash, scan, or materialized drift fails closed. Reopen may complete a validated partial publish, but it cannot invent or revise judgment content.
