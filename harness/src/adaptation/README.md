# Adaptation Runtime Ownership

G0.4 implements deterministic Discovery Plan Gap Snapshot drafts, Discovery Adaptation Decision policy checks, immutable Plan Revision application, stale-base compare-and-swap behavior, retry/supersede lineage, late Artifact exclusion, idempotency, and crash-boundary recovery.

The public `author-plan-adaptation` path is a current-only authoring surface over those owners. A Main Agent submits explicit machine and semantic Gap inputs plus Adaptation Decisions. `validate_only` returns the exact Gap/Decision/Plan publication plan without normal writes; `publish` requires that exact plan and atomically publishes the Gap Snapshot and Decisions; `apply` requires the post-publication plan and delegates the Plan transition to `PlanRevisionRuntime`. It derives only mechanical fields and exact current-Run refs/hashes. It preserves explicit partial, blocked, insufficient-evidence, conflict, and terminal inputs without selecting evidence or inferring relations. A post-Manifest crash can be replayed from the same immutable publication plan; read-only validation never completes a pending Plan receipt.

`PlanSemanticValidator` enforces one domain-specific closed Research Plan contract: DAG and dependency legality, unique unit/output ownership, exact mode/phase/unit_type/agent_role/required_artifact_schema tuples, Planning Context v2/source bindings, AI mandatory coverage, manifest dispositions, and immutable parent constraints. It is not a general DAG language or workflow runtime.

`GapAnalyzer` consumes an explicit validated Document Bundle, derives machine-observable gaps, and preserves explicit semantic gap inputs without selecting or interpreting them. Its cycle identity binds the base Plan ref/hash, trigger kind, exact wave id or event ref/id, and observed Artifact hashes; path-like refs require an exact target and fragment, and event-driven analysis requires a same-Run `startup_opportunity.event.v1`. Semantic gap selection remains with the main agent. `AdaptationPolicyValidator` dispatches from the Run Manifest mode and accepts only the matching current Discovery or Assessment closed actions; retry requires `failed_units`, partial retry fails closed, and `continue_existing_plan` verifies rather than interprets the main agent's Coverage Attestation.

`PlanRevisionRuntime` first checks every explicit non-manifest adaptation policy input against its validated immutable on-disk envelope and effective document without scanning unrelated Run contents. It then writes an immutable operation receipt, publishes control Artifact paths, performs manifest CAS, and publishes a checkpoint plus append-only events. Replay is idempotent by canonical parent Plan hash plus sorted Adaptation Decision refs. Recovery completes only validated on-disk receipt state; late Artifact files persist but remain outside current `artifact_refs`.

`terminate_insufficient_evidence`, `record_runtime_failure`, `complete_research`, and `cancel_research` require an explicit main-agent terminal report source in the apply input. `complete_research` is valid only when every current Plan unit has a non-failed terminal disposition and no current unclosed Gap remains. `cancel_research` requires an exact same-Run user `run_cancelled` Decision; the Harness mechanically moves current pending or active units to `cancelled_units` while preserving truthful failed history. `record_runtime_failure` remains valid only for a blocking `runtime_blocked` Gap and terminates the original Run as `failed`, without turning an execution failure into a research conclusion.

All four outcomes use the same durable Plan operation. The Runtime validates the exact Adaptation action, authority, report outcome, and source bindings before writes, publishes every formal report Artifact and materialized view before the Manifest-last status transition, then publishes the checkpoint and events. Recovery revalidates the same immutable action/outcome closure and completes that intent idempotently. The source remains caller judgment; the Harness only validates, derives localized views, publishes, and recovers them.

`discovery-adaptation-binding.v1.json` adds the G2 `candidate_pre_killed -> skip_unit` boundary without changing generic G0/G1 policy bytes. The Gap subject must be one exact typed candidate path and the pending/enabled target unit must contain that exact revision as its only candidate-shaped input. Units shared with another retained candidate remain enabled or require an explicit superseding unit; apply and replay re-run the same validator before any Plan transform becomes current.

G1.3 adds `AssessmentGapAnalyzer` and assessment policy validation for buyer/acquisition coverage only. An Assessment Gap Snapshot binds exact same-Run subject/scope/current Research Plan/assessment plan, canonical `coverage_key`, observed Branch Result and Research Task hashes, plus unit/attempt state. A valid Assessment `add_unit` decision publishes immutable Research Plan r2, assessment plan r2, and Planning Context r2 as one pending control bundle before Manifest CAS; `stop_followup` publishes no Plan revision. The Assessment Plan operation receipt validates base/result assessment plan hashes during replay and recovery. This remains a bounded domain transform, not a general workflow runtime or arbitrary DAG DSL.
